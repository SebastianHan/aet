# 精益创业验证流程

## 定位

当新产品探索、资源有限、需要快速验证假设时使用。精益创业把问题当作"可验证假设"，用证据而非直觉推进。

---

## 核心概念：Build-Measure-Learn循环

```
Build（构建） → Measure（测量） → Learn（学习） → 循环
```

- **Build**：构建最小可行产品（MVP）
- **Measure**：收集验证数据
- **Learn**：从数据中学习，决定 Pivot 或 Persevere

---

## 1. 假设清单生成

### 两类核心假设

1. **价值假设（Value Hypothesis）**
   - 这个问题是否真实且重要？
   - 用户会真正使用我们的解决方案吗？
   - 愿意为此付费吗？

2. **增长假设（Growth Hypothesis）**
   - 问题解决后是否会可持续扩散？
   - 用户会推荐他人吗？
   - 如何获取更多用户？

### 假设优先级

按风险高低排序：

| 优先级 | 假设类型 | 验证重要性 |
|--------|---------|-----------|
| P0 | 核心价值假设 | 必须验证 |
| P1 | 主要增长假设 | 尽快验证 |
| P2 | 运营假设 | 有空验证 |

### Agent执行要点

- 为每个假设定义"验证成功标准"
- 避免验证模糊假设，如"用户喜欢这个功能"

---

## 2. 客户发现四阶段

### 阶段1：问题发现（2-4周）

**目标**：验证是否真实存在一个痛苦的、可解决的问题

**行动**：
- 进行15-20次深度用户访谈
- 使用question-templates.md中的痛点挖掘问题集
- 识别"高频、高损失、强情绪"痛点

**验证标准**：
- 至少70%访谈对象表示这是真实痛点
- 痛点影响足够大，用户主动寻求解决方案

**输出**：
- 问题优先级列表
- 痛点验证报告

### 阶段2：解决方案验证（2-3周）

**目标**：验证我们提出的解决方案是否有效

**行动**：
- 向用户展示概念/原型
- 进行10-15次访谈测试
- 收集偏好和支付意愿

**验证标准**：
- 用户对解决方案表现出兴趣
- 用户愿意给出联系方式或预付定金

**输出**：
- 解决方案偏好排序
- 早期意向用户清单

### 阶段3：MVP定义（1-2周）

**目标**：定义最小可行产品

**行动**：
- 基于前两阶段洞察定义MVP范围
- 确定MVP类型（纸质原型/功能原型/Concept MVP）
- 制定验证实验计划

**MVP类型选择**：

| 类型 | 成本 | 验证能力 | 适用场景 |
|------|------|---------|---------|
| 概念验证 | 极低 | 概念接受度 | 早期探索 |
| 纸质原型 | 低 | 流程可行性 | 界面/交互 |
|  landingspage | 低 | 价值主张 | 市场需求 |
| Concierge MVP | 中 | 核心价值 | 定制化服务 |
| 功能原型 | 中高 | 实际使用 | 需真实体验 |

**输出**：
- MVP定义文档
- 验证实验设计

### 阶段4：PMF信号（持续）

**目标**：验证产品-市场匹配

**关键指标**：
- 用户留存率
- 用户推荐意愿（NPS）
- 用户参与度
- 收入增长

**判断标准**：
- 有机增长率 > 5%/周
- 用户留存曲线趋于平稳
- NPS > 40

## 3. Mom Test访谈原则

### 核心三原则

1. **谈他们的生活，而非你的想法**
   - 避免：询问对的想法
   - 改问：描述你最近一次遇到X问题的情况

2. **问过去具体行为，而非未来假设**
   - 避免：你会使用这个功能吗？
   - 改问：上次遇到这个问题你做了什么？

3. **倾听80%时间**
   - 让用户说话
   - 追问细节和感受

### 访谈问题示例

| 避免问 | 改问 |
|--------|------|
| 你觉得这个APP怎么样？ | 上周你用什么方式解决X问题？ |
| 你会购买这个产品吗？ | 你目前在这方面花了多少钱？ |
| 你觉得这个功能重要吗？ | 没有这个功能时你怎么办的？ |

## 4. 验证实验设计

### 实验类型

1. **Concierge测试**
   - 人工服务少数真实用户
   - 验证核心价值，而非规模化

2. **Landing Page测试**
   - 验证价值主张吸引力
   - 收集邮件注册

3. **烟雾测试**
   - 用简单页面验证需求
   - 不实现实际功能

4. **A/B测试**
   - 验证具体方案差异
   - 需要足够流量

### 实验记录模板

```
实验名称：XXX验证
假设：[具体假设]
验证方式：[Concierge/Landing Page/A/B]
样本：N=XX
结果：[数据]
结论：[通过/失败/不确定]
下一步：[Pivot/Persevere/迭代]
```

## 5. Pivot vs Persevere决策

### 何时Pivot

- 关键假设验证失败
- 用户反馈持续负面
- 核心指标长期无改善

### Pivot类型

| 类型 | 适用情况 |
|------|---------|
| Zoom-in Pivot | 单一功能成为核心 |
| Zoom-out Pivot | 功能过于窄众 |
| Customer Segment Pivot | 目标用户不对 |
| Platform Pivot | 从产品转向平台 |
| 技术Pivot | 技术方案不可行 |

### 何时Persevere

- 核心假设被验证
- 用户参与度提升
- 有明确改进路径

## 使用场景判断

选择lean-startup-guide.md当：
- 用户说"先验证市场是否存在"
- 资源有限，需要小步快跑
- 方向不明确，需要探索
- 听到"我们要做XXX功能"

不选择当：
- 需求已明确，有成熟市场
- 技术方案是唯一瓶颈
- 资源充足，可以大规模投入
- 市场验证已完成，只需执行
