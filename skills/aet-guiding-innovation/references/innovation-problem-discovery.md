# 创新问题发掘与定义（汇总版）

## 文档定位

本文件用于统一沉淀“创新本身”的方法论，重点覆盖：
- 创新的定义与判断标准
- 问题发掘与机会识别
- 问题重构与优先级判断

## 一、创新的定义（聚焦“创新本身”）

创新不是“做新东西”本身，而是通过新的问题理解与价值重构，创造可感知的新价值。

可从 3 个层面判断是否构成创新：
- **问题层**：是否发现了过去被忽略、误判或未被清晰定义的问题。
- **价值层**：是否为特定用户群体带来显著的新价值（而非仅功能堆叠）。
- **结构层**：是否改变了原有竞争维度、认知边界或价值分配方式。

## 二、问题发掘总流程

```
用户与场景洞察 -> 问题定义 -> 问题重构 -> 机会筛选
```

### 1) 用户与场景洞察
- 明确“谁在什么情境下遇到什么阻碍”
- 区分表面诉求与真实动机
- 识别任务链条中的高摩擦节点

### 2) 问题定义
- 使用单句问题陈述：`某类用户在某情境下，因某原因无法达成某目标`
- 避免“预设解法”的问题表述（如直接把方案写进问题）

### 3) 问题重构
- 用不同视角重述问题，扩展机会空间
- 常用模板：How Might We（我们可以如何…）

### 4) 机会筛选
- 以“价值潜力 × 可行性 × 差异化”进行初筛
- 保留高价值高确定性问题，标记高价值高不确定性问题进入后续验证

## 三、六种方法论的“问题发掘”贡献

### 1) 设计思维（Design Thinking）
- 核心贡献：从“用户视角”定义问题，而非从既有能力出发。
- 问题发掘重点：
  - 同理心访谈与观察
  - 用户旅程中的痛点、情绪波动与断点
  - How Might We 问题重构
- 典型输出：
  - Persona（用户画像）
  - 用户旅程地图
  - 问题陈述（POV）

### 2) 精益创业（Lean Startup）
- 核心贡献：把问题当作“可验证假设”，用证据而非直觉推进。
- 问题发掘重点：
  - 价值假设：这个问题是否真实且足够重要
  - 增长假设：问题一旦解决是否可持续扩散
  - 验证性学习：每轮需要学到什么
- 典型输出：
  - 假设清单
  - 假设优先级
  - 关键学习问题

### 3) 蓝海战略（Blue Ocean）
- 核心贡献：从“竞争比较”转向“价值重构”，发现非竞争空间。
- 问题发掘重点：
  - 四步动作：消除 / 减少 / 提升 / 创造
  - 六条路径：替代行业、战略群组、买方群体、互补环节、功能情感、时间趋势
  - 挑战行业默认前提
- 典型输出：
  - 待消除的低价值惯例
  - 待创造的新价值维度
  - 潜在蓝海机会陈述

### 4) TRIZ
- 核心贡献：把复杂问题显式化为“矛盾”，系统化找突破口。
- 问题发掘重点：
  - 识别技术矛盾与物理矛盾
  - 明确“改善什么会恶化什么”
  - 用 IFR（理想最终解）逼近问题本质
- 典型输出：
  - 矛盾定义表
  - 关键冲突参数
  - IFR 问题陈述

### 5) 商业模型画布 / 价值主张画布
- 核心贡献：把“用户问题”与“价值结构”对齐，避免伪需求。
- 问题发掘重点：
  - Customer Jobs / Pains / Gains
  - 哪些痛点高频、高损失、强情绪
  - 哪些客户细分尚未被满足
- 典型输出：
  - 客户任务-痛点-收益画像
  - 优先痛点清单
  - 问题-价值匹配假设

### 6) 开放式创新（Open Innovation）
- 核心贡献：将问题发掘边界从组织内部扩展到外部网络。
- 问题发掘重点：
  - 外部趋势与技术信号扫描
  - 与合作方/生态伙伴联合识别问题
  - 识别“内部看不见、外部先看见”的机会
- 典型输出：
  - 外部机会列表
  - 合作问题池
  - 生态协同方向

## 四、统一问题发掘清单

在进入方案设计前，至少回答以下问题：
- 我们定义的是“用户问题”，还是“我们想做的方案”？
- 问题是否对应明确用户群体与场景？
- 问题是否有可观察证据支持（行为、反馈、数据）？
- 该问题是否值得优先处理（价值、紧迫性、影响范围）？
- 问题是否具有差异化空间（不是所有人都在同样解决）？

## 五、建议产出模板（仅问题侧）

```
问题发掘摘要
1. 目标用户与关键场景
2. 核心问题陈述（不含解法）
3. 证据来源与关键观察
4. 问题重构（How Might We）
5. 机会优先级（高/中/低）
6. 待验证的关键不确定性
```
