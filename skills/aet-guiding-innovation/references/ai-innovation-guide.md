# AI时代创新方法

## 定位

当进行AI产品设计、智能解决方案创新、或需要利用多Agent协作提升创新效率时使用。

---

## 核心框架概览

| 框架 | 核心机制 | 适用场景 |
|------|---------|---------|
| EXPERIGEN | Generator + Experimenter 双Agent循环 | 假设驱动的研究发现 |

## EXPERIGEN双Agent框架

### 核心原理

基于贝叶斯优化灵感的双Agent循环：
- **Generator Agent**：生成候选假设
- **Experimenter Agent**：设计验证实验，评估假设质量

### 5步工作流

```
1. Generator生成假设候选
2. Experimenter设计验证实验
3. 执行实验获取数据
4. Experimenter评估结果
5. Generator基于反馈生成新假设 → 循环
```

### 操作步骤

#### Step 1: 定义研究问题

- 明确要解决的问题
- 定义成功标准
- 确定可用的验证方法

#### Step 2: Generator初始化

- 提供领域背景知识
- 设置假设生成约束
- 启动假设生成

#### Step 3: Experimenter评估

- 对每个假设设计验证实验
- 评估维度：
  - 新颖性（与已知比较）
  - 可验证性（有方法验证）
  - 潜在影响（如果正确）
  - 可行性（当前可测试）

#### Step 4: 反馈循环

- Experimenter将评估反馈给Generator
- Generator基于反馈调整假设空间
- 迭代直到找到高质量假设

#### Step 5: 结果整合

- 收集所有验证结果
- 识别最 promising 的方向
- 制定后续研究计划

### Agent执行要点

- Generator和Experimenter需要独立 prompt 模板
- 设置迭代次数限制（如10轮）
- 记录每轮的假设和评估理由

### 效果指标

- 发现2-4倍于基线的显著假设
- 假设预测性提升7-17%
- 88%被专家评为中等或高度新颖

## MIDAS分布式多Agent系统

### 核心原理

Meta-cognitive Ideation through Distributed Agentic AI System：
- 使用分布式专业Agent
- 分工探索问题的不同角度
- 汇总后进行多轮精化
- 人类从被动过滤者变为主动协作伙伴

### 4阶段流程

```
阶段1: 分工探索 → 阶段2: 汇总整合 → 阶段3: 迭代精化 → 阶段4: 人类协作
```

#### 阶段1: 分工探索

- 根据问题拆解为子问题
- 每个Agent负责一个角度
- Agent类型：
  - 用户洞察Agent
  - 技术可行性Agent
  - 市场机会Agent
  - 风险评估Agent

#### 阶段2: 汇总整合

- 收集各Agent的发现
- 识别交叉点和共识
- 标记冲突和不确定性

#### 阶段3: 迭代精化

- 人类选择感兴趣的发现
- 触发相关Agent深入分析
- 重复直到洞察足够清晰

#### 阶段4: 人类协作

- 人类作为主动参与者而非被动审核
- 基于AI提供的洞察做最终判断
- 人机协作产生最终创新方案

### Agent执行要点

- 每个Agent有明确的角色定义
- 汇总时使用结构化模板
- 保留探索过程中的多样性

### 效果指标

- 显著提升假设的全局和局部新颖性评估
- 人类从过滤器转变为协作者

## 可解释创新引擎

### 核心原理

将方法作为节点而非文本块：
- 维护加权方法溯源树
- 支持可追溯的推导过程
- Strategy Agent选择显式综合操作符
- 验证层修剪低质量候选

### 关键组件

| 组件 | 功能 |
|------|------|
| 方法节点 | 将方法论表示为可追溯节点 |
| 溯源树 | 记录方法的来源和推导过程 |
| Strategy Agent | 选择综合操作符（归纳/演绎/类比） |
| Verifier-Scorer | 评估和修剪低质量候选 |

### 操作流程

1. **方法表示**：将方法论转化为结构化节点
2. **溯源追踪**：记录每个方法的应用历史
3. **综合生成**：使用操作符组合生成新方法
4. **验证评分**：评估生成方法的质量
5. **迭代优化**：保留高质量，淘汰低质量

### Agent执行要点

- 维护方法节点的知识图谱
- 记录每次推理的溯源信息
- 使用多操作符增加多样性

## AI创新方法的选择

### 选择建议

| 场景 | 推荐框架 |
|------|---------|
| 需要验证具体假设 | EXPERIGEN |
| 复杂问题多角度探索 | MIDAS |
| 需要可追溯的创新过程 | 可解释创新引擎 |
| 探索性研究，早期阶段 | EXPERIGEN |
| 已有方向，需要深化 | MIDAS |
| 创新审计/合规要求 | 可解释创新引擎 |

### 组合使用

- 可以先用EXPERIGEN生成候选
- 再用MIDAS深化最 promising 的方向
- 最后用可解释创新引擎确保可追溯性

## AI创新的特殊考量

### 数据驱动

- AI产品高度依赖数据质量
- 需要考虑数据的可用性和偏见

### 伦理合规

- 隐私保护
- 算法公平性
- 可解释性要求

### 人机协作

- AI擅长模式识别和大规模探索
- 人类擅长判断和价值选择
- 最佳实践：AI生成，人类决策

### 快速迭代

- AI产品迭代周期短
- 需要建立快速的假设验证机制
- 拥抱"失败即学习"文化

## 使用场景判断

选择ai-innovation-guide.md当：
- 开发AI相关产品或功能
- 需要多角度探索复杂问题
- 研究性问题需要可追溯性
- 想要利用多Agent协作提升效率

不选择当：
- 传统产品/服务创新
- 不涉及AI技术方案
- 只需要单一角度分析
- 时间极短，需要快速交付
