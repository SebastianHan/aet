# 需求设计检查表

本检查表用于评审需求设计说明书的质量。检查项直接对应模板 `assets/requirements-design-template.md` 的结构。

---

## §1 概要

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 名称是否与需求分析一致 | ERROR | 必须与需求分析说明书一致 |
| 描述是否清晰 | WARNING | 设计层面一句话描述 |
| 输入来源是否标注 | ERROR | 需求分析说明书路径/版本 |
| 项目类型是否正确 | WARNING | `Feature Enhancement / New Feature / Refactoring` |

---

## §2 SR-AR 分解与追溯

### 2.1 SR 列表

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| SR 编号是否规范 | WARNING | 格式 `SR-001` |
| SR 数量是否合理 | ERROR | 一般 1-2 个；超过 3 个需用户确认必要性 |
| 对应场景是否标注 | WARNING | 每个 SR 对应需求分析中的主要场景或功能域 |
| 覆盖功能是否说明 | WARNING | F-01, F-02 等功能编号 |

### 2.2 AR 分配

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| AR 编号是否规范 | WARNING | 格式 `AR-001-01`，关联 SR 编号 |
| 每个 SR 的 AR 数量是否合理 | ERROR | 默认 1-2 个，最多 3 个；超过需确认拆分理由 |
| 一 AR 一元素原则 | ERROR | 每个 AR 属于且仅属于一个系统元素（模块/组件/服务） |
| 功能点是否列出 | ERROR | 每个 AR 必须列出具体功能点，禁止模糊描述 |
| 系统元素是否明确 | ERROR | 模块名及操作类型（新增/扩展/依赖） |

---

## §3 架构设计

### 3.1 架构变更总览

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| Mermaid 架构变更图是否绘制 | ERROR | 展示新增🟢/修改🟡/保护🔴/不涉及⚪模块及调用关系 |
| 图例是否标注 | WARNING | 颜色含义：🔵外部用户、🟢新增、🟡修改、🔴保护、⚪不涉及 |
| 接口命名是否规范 | WARNING | 格式 `IF-{Type}{Number}`：E=外部、N=新增内部、M=修改内部、R=复用内部 |

### 3.2 模块说明

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 遗留模块是否有简要说明 | WARNING | 为修改/保护模块提供简要说明，帮助用户快速了解现状 |

### 3.3 模块变更明细

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 变更状态是否明确 | ERROR | 🟢新增 / 🟡修改 / 🔴保护 / ⚪不涉及，四类状态标注 |
| 变更描述是否具体 | ERROR | 每个模块的变更类型、范围、原因已说明 |
| 约束是否说明 | WARNING | 仅允许修改特定流程、禁止修改接口签名等 |
| 是否只列出相关模块 | INFO | 控制粒度，无需展开无关模块 |

### 3.4 依赖矩阵

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 依赖矩阵是否绘制 | WARNING | 模块间关系：扩展/依赖/新增/无关系 |
| 注释是否说明 | INFO | Extension=修改现有、Dependency=调用不修改、New=全新创建 |

### 3.5 功能影响列表

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 功能树是否展示 | WARNING | 系统/模块 → 功能域 → 功能点 层级结构 |
| 变更类型是否标注 | WARNING | 新增/修改/删除 |
| 对应需求是否追溯 | ERROR | 每个变更追溯到 SR 编号 |

---

## §4 核心流程

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 流程图是否绘制 | WARNING | 根据设计需要选择合适的图表类型：sequenceDiagram、stateDiagram-v2、flowchart |
| 流程图是否有实际设计价值 | INFO | 仅包含有实际设计价值的图表，不适用的部分可省略 |
| 图表语法是否正确 | WARNING | Mermaid 图表语法正确，可渲染 |

## §5 DFx 设计

### 5.1 性能

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 指标是否继承自需求分析 | | 关键操作响应时间等指标与需求分析说明书一致 |
| 测量条件是否明确 | WARNING | 并发条件、数据规模等已说明 |
| 模块分解是否合理 | WARNING | 系统级目标分解到模块/链路节点，有时间分配和分解依据 |
| 假设条件是否说明 | INFO | 无明确数据时标注"待确认"，禁止虚构 |

### 5.2 可用性 / 可靠性

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 设计关注点是否列出 | WARNING | 容错降级、超时重试、熔断隔离、幂等设计、一致性、监控告警、故障恢复等 |
| 方案决策是否具体 | WARNING | 具体措施如"超时 300ms + 最大重试 1 次 + 熔断降级" |
| 故障场景预案是否定义 | WARNING | 故障场景、系统表现、应对策略、恢复判断 |
| 影响范围/取舍是否说明 | INFO | 受影响链路和权衡 |

### 5.3 技术债与兼容性风险

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 风险项是否列出 | WARNING | 向后不兼容、隐式依赖、循环依赖等风险 |
| 缓解措施是否说明 | WARNING | 避免或缓解计划 |

### 5.4 [XXX]

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| DFx 设计是否按需扩展 | INFO | 根据需要扩展 DFx 设计，包括安全性、易用性、可扩展性、可测试性等方面 |

| 检查项 | 严重程度 | 检与其他要点 |

## 文档一致性检查

| 检查项 | 严重程度 | 检查要点 |
|--------|----------|----------|
| 架构变更图与模块变更明细是否一致 | ERROR | 图中标注的模块状态（🟢/🟡/🔴/⚪）与模块变更明细表格完全一致 |
| 架构变更图与接口设计是否一致 | ERROR | 图中的接口调用关系与接口设计章节定义的接口编号、提供方、消费方一致 |
| 模块变更明细与模块详细设计是否一致 | WARNING | 模块变更明细中标注的变更模块在模块详细设计中有对应设计（如有） |
| 接口定义与架构变更图中的接口调用是否一致 | ERROR | 接口定义中的所有接口都在架构变更图中有对应的调用关系标注 |
| 功能影响列表与 SR-AR 分解是否一致 | ERROR | 功能影响列表中的变更类型和功能点与 SR-AR 分解中的功能点对应一致 |
| 依赖矩阵与架构变更图中的调用关系是否一致 | WARNING | 依赖矩阵中的模块间关系与架构变更图中的连线关系一致 |
| 核心流程与接口设计是否一致 | WARNING | 核心流程图中涉及的接口调用在接口设计中有定义 |
| 核心流程与模块变更明细是否一致 | WARNING | 核心流程图中涉及的模块在模块变更明细中有标注 |
